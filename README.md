# Heli bot

Десктопный ассистент для компаний в РФ. Клиент — Tauri 2 (Windows и macOS) и та же веб-оболочка. Сервер — FastAPI. Модели вызываются только с сервера, ключ `HELI_API_KEY` живёт в окружении и в секрете GitHub Actions, не в клиенте и не в репозитории.

v0.1: чат, облачный браузер, простые действия на компьютере с подтверждением, доступы, расписания, процент лимита, журнал, отзыв. Не входит: оплата, роли, маркетплейс коннекторов, своя модель, голос, мобильное приложение.

## Репозиторий

- `apps/desktop` — Tauri 2 + React
- `apps/web` — веб-версия того же интерфейса
- `packages/ui` — общая оболочка. Визуал — заглушки с `data-design-slot`; макет и маскот подставляет отдельный дизайн-проект
- `server` — оркестратор
- `browser` — образ Chromium + noVNC, один контейнер на пользователя
- `infra` — docker-compose: api, Postgres (pgvector), Redis, Caddy

Публичные алиасы моделей: `heli-fast`, `heli-fast-alt`, `heli-vision`, `heli-vision-lite`, `heli-smart`, `heli-smart-alt`. Клиент и публичное API других имён не показывают.

Интерфейс собран по макетам из `design/` (описание — `design/README.md`): вход, чат с панелью «Компьютер агента» и карточкой подтверждения, лимиты с полосой (предупреждение с 80%, жёсткий стоп на 100%), настройки и подключения, светлая и тёмная темы. Состояния маскота: ожидает, думает, работает, готово.

## Локально

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e "./server[dev]"
pytest server/tests

pnpm install
pnpm typecheck
pnpm --filter @heli/web dev
```

Сервер: `python -m app.main` из каталога `server` (слушает `0.0.0.0:$PORT`). Ключ модели: переменная окружения `HELI_API_KEY`. Пример остальных переменных — `.env.example`.

Инфраструктура: `docker compose -f infra/docker-compose.yml up --build` (нужен Docker и `HELI_API_KEY` в окружении).

Десктоп: `pnpm --filter @heli/desktop tauri dev`. Сборка без подписи — позже, в этапе релиза. На macOS без подписи Gatekeeper, на Windows SmartScreen предупредит.

## Доступ в интернет

Агент сам ищет в сети и открывает страницы: на сервере ему доступны инструменты `web_search` и `open_url` (до 6 раундов вызова инструментов за ответ, каждый шаг пишется в журнал). Страницы читаются без ключей, адреса локальной и частной сети запрещены. Для поиска нужен ключ Yandex Search API (`YANDEX_SEARCH_API_KEY` и `YANDEX_SEARCH_FOLDER_ID` в `.env`) или Tavily (`TAVILY_API_KEY`). Без ключа поиск идёт только по Википедии. Явно выбрать поставщика можно через `HELI_SEARCH_PROVIDER=yandex|tavily|wikipedia`.

Управление браузером в панели «Компьютер агента» этим не покрыто: локальный Chrome открыт на компьютере пользователя, и шаги в нём должен выполнять десктоп-клиент.

## Лимиты и журнал

Тестерам показывается процент недели и месяца, на 100% задача останавливается.

Траектории пишутся с первого дня для будущего дообучения. Обучения в v0.1 нет. Запись в журнал создаётся только при отдельном согласии (по умолчанию выключено). В ней запрос, контекст, каждый шаг (мысль, план, алиас модели, ответ, инструмент и аргументы, результат, DOM или ссылка на скриншот), токены и стоимость, ошибка и номер попытки, итог и оценка: палец вверх или вниз, принято или правка.

Документ лежит в Postgres. Выгрузка для администратора: `GET /v1/admin/trajectories.jsonl?kind=raw|sft|dpo`. SFT по умолчанию берёт только успешные задачи, `success_only=true` оставляет их и в сыром журнале. Пароли и персональные данные маскируются. `HELI_API_KEY` в журнал и в логи не попадает.

Все лимиты считаются по аккаунту: день (`DAILY_LIMIT_RUB`, 0 — без дневного лимита), неделя и месяц (`DEFAULT_MONTHLY_LIMIT_RUB`, по умолчанию 1000 ₽; неделя — месяц / 4 × 1,25). Общий на весь сервер дневной потолок включается только явно: `GLOBAL_DAILY_LIMIT_RUB` больше нуля (по умолчанию выключен). Админ меняет недельный и месячный лимит конкретного пользователя в блоке «Тестеры» или `PATCH /v1/admin/users/{id}/limit` (`weekly_limit_rub: 0` возвращает автоматическую неделю), оператор — `python -m app.cli set-limit --email ... --weekly ... --monthly ...`.

### Доступ: платная бета и учебный аккаунт

- `HELI_OPEN_ACCESS=1` — только для закрытого стенда: все получают токен одного общего аккаунта (`POST /v1/auth/open`, почта `HELI_OPEN_ACCESS_EMAIL`, по умолчанию `owner@heli.local`). Для тестеров не включать.
- `HELI_OPEN_ACCESS=0` (общий сервер с тестерами) — у каждого свой аккаунт. Токены, выданные `/v1/auth/open`, и старые токены общего аккаунта не принимаются. Деплой `deploy-shared-server` ставит 0 сам.
- `HELI_INVITE_ONLY=1` (по умолчанию) — регистрация только с кодом приглашения. Почты из `HELI_ADMIN_EMAILS` регистрируются без кода и видят блок «Тестеры»: приглашения, коды входа и сброса, список аккаунтов, лимиты. Админ должен зарегистрироваться сразу после деплоя: пока почта не подтверждается, регистрацию на эту почту может занять любой, кто её знает.
- `HELI_TRAINING_EMAILS` — внутренние учебные аккаунты для прогонов пакетов (никогда не админы). Если туда входит `owner@heli.local`, бывший общий аккаунт остаётся со своим vault (вебхук Битрикс24, учебные доступы), задачами и квотами. Ему нужен новый токен: код входа от админа или `python -m app.cli training-token --email owner@heli.local` (печатает токен на 14 дней, не публиковать). Деплой дописывает `HELI_TRAINING_EMAILS=<HELI_OPEN_ACCESS_EMAIL>`, если ключа нет.

Почта для кода входа ещё не отправляется. Пока SMTP не подключён, оператор выдаёт код из каталога `server`, а клиент после «Получить код» или «Отправить код» сразу показывает поле для него:

- новый пользователь по приглашению: `python -m app.cli create-invite`, затем `python -m app.cli issue-code --email ... --invite ...`;
- вход по коду для существующего аккаунта: `python -m app.cli issue-code --email ...`;
- сброс пароля: `python -m app.cli issue-reset-code --email ...`.

Код живёт 10 минут. Нужны `JWT_SECRET` и `TRAJECTORY_HASH_PEPPER` в окружении.

## Навыки для 1С, Битрикс24, amoCRM

`server/app/skills` — подсказки агенту по интерфейсам этих систем и вход через vault. Цикл агента добавляет `guide_for(запрос, адрес)` в системный промпт шага: что где лежит, адреса разделов, как ведёт себя интерфейс, какие действия опасны и требуют подтверждения. `login_steps` отдаёт шаги входа, где пароль — плейсхолдер `<CREDENTIAL:id>`. Настоящий пароль подставляет `resolve_secret_args` прямо перед отправкой действия в браузер, только в поле ввода и только если браузер на сайте этого доступа. Модель и журнал видят плейсхолдер.

## Реклама, маркетплейсы и почта

Инструменты агента для малого бизнеса (`server/app/agent`). Боевые кабинеты только читаются, записи в бою нет ни в одном инструменте.

- `http_request` (`http_tool.py`) — любой HTTP-запрос к API. Ключи пишутся как `{{secret:ИМЯ}}` (ИМЯ — сайт записи в «Доступах» или сайт/логин), сервер подставляет ключ только для запросов на хост этой записи и вырезает его из ответа. GET и HEAD — чтение; POST в бою — только по белому списку читающих эндпоинтов (Ozon `…/list`, `…/info`, Директ `method: get` и `reports`). Изменения — только в песочницах (`api-sandbox.direct.yandex.com`, плюс `HELI_HTTP_SANDBOX_HOSTS`).
- `mail_read` (`mail.py`) — IMAP: папки, список, поиск, письмо, вложения. Папка открывается через EXAMINE, письма через `BODY.PEEK[]`: «прочитано» не ставится. `mail_send` появляется только при `HELI_MAIL_SEND=1` и всегда идёт через подтверждение пользователя.
- `direct_api` и `metrika_read` (`yandex_direct.py`) — Директ API v5 (`get` в бою, `add/update/…` только с `sandbox=true`), отчёты TSV с ожиданием 201/202 по `retryIn`, Метрика только GET. OAuth-токен — в «Доступах»: сайт `direct.yandex.ru`, логин `token`. Кабинет на экране работает под сохранённым входом облачного браузера; капчу агент не решает, а ставит паузу и просит пользователя.
- `ga4_read` и `ga4_send_event` (`google_analytics.py`) — Google Analytics 4. Чтение: Data API `runReport` / `runRealtimeReport` / `metadata` и Admin API только GET (`key_events`, `data_streams`, `account_summaries`); ключ в «Доступах»: сайт `analytics.google.com`, логин `token` (OAuth) или `service_account` (JSON-ключ, сервер берёт токен с областью `analytics.readonly`). Тестовые хиты Measurement Protocol — только на учебный Measurement ID: `HELI_GA4_SANDBOX_IDS` или запись «Доступов» с сайтом `ga4-sandbox` (логин — ID, пароль — API secret; создаёт только пользователь, не агент). Чужой или боевой ID — отказ до чтения ключа и без запроса в сеть. Адреса сбора хитов (`google-analytics.com`, `…/g/collect`, `mc.yandex.*`) закрыты для `http_request` и `open_url` при любом методе. Боевые ID getheli и клиентов в репозиторий и в учебный список не кладутся.

## База знаний и «изучи предмет»

`server/app/knowledge.py` — своя база знаний Heli (таблица `knowledge_notes`): правило, источник, дата проверки. Перед задачей подходящие записи попадают в промпт; агент сам ищет (`knowledge_search`), сохраняет проверенные выводы после удачной задачи (`knowledge_save`, источник обязателен, данные клиента маскируются) и помечает устаревшее (`knowledge_mark_stale`; записи старше 180 дней показываются как «устарело, перепроверь»). Стартовое наполнение — правила Директа (`SEEDS`), в том числе: конверсионные стратегии только при ≥10 конверсий в неделю.

Если задача про сервис или тему, которых нет ни в навыках, ни в базе, цикл агента требует шаг «изучи предмет»: первое действие или ответ ждут `knowledge_search` / `web_search` / `open_url`. Поиск ставит официальную справку и документацию API первыми.

## После v0.1

В эту версию не входит и сейчас не делается.

- Бесплатная неделя: лимит в процентах.
- «Облако» через getheli: ориентир 3–5 тыс. ₽ в месяц на компанию.
- «Закрытый» на сервере в РФ, данные не уходят: ориентир 15–25 тыс. ₽ в месяц.
- Позже понадобятся страница тарифов, счёт от ИП, учёт оплаты и ручное включение плана администратором. Онлайн-кассы нет. Банковские реквизиты в репозиторий не кладутся.

## CI

Один workflow, только `pull_request`. Тесты сервера и проверка типов фронта. Смоук маршрутизатора читает секрет `HELI_API_KEY` из GitHub Actions. Локально тот же ключ берётся из переменной окружения. Значение не печатается и в репозиторий не входит.
